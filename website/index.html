01 · Getting started

From clone to healthy in minutes

Docker Compose starts both the API and MongoDB. No paid account or hosted service is required.

  1. 1

    Prepare configuration

    cp .env.example .env

    For local development, the defaults are ready to use. Never reuse the example JWT secret in a public deployment.

  2. 2

    Start the stack

    docker compose up --build

    The API listens on port 8080 and MongoDB on 27017.

  3. 3

    Check readiness

    curl http://localhost:8080/health/ready

    A ready service returns {"status":"ready"}.

Development email

Invitation and password-reset links are written to application logs. Production mode requires SMTP credentials and never logs these tokens.

03 · Authentication

Access tokens stay short. Sessions stay controllable.

Login returns a signed access token and an opaque refresh token. Refresh tokens rotate every time they are used.

1Login

Credentials are checked against bcrypt and the active organization membership.

2Issue

A JWT and a random refresh token are returned. Only the refresh-token hash is stored.

3Rotate

Every refresh replaces the current token. Reuse of an old token revokes the session.

4Revoke

Users can end one session or all sessions for the organization.

Authenticated request

curl http://localhost:8080/api/v1/auth/me \
  -H "Authorization: Bearer $ACCESS_TOKEN"

05 · Team onboarding

Single-use invitations

Owners and admins can invite members without sharing credentials or pre-creating passwords.

Token handling

Invitation tokens are random, stored only as hashes, expire automatically, and can be accepted only once.

curl -X POST http://localhost:8080/api/v1/organizations/current/invitations \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"teammate@example.com","role":"member"}'
06 · Account recovery

Recovery without account discovery

Password-reset requests always return the same accepted response, whether the email exists or not. Reset tokens are hash-only, expiring, and single-use. A successful reset revokes all sessions for that user.

POST/api/v1/auth/password/reset-request
POST/api/v1/auth/password/reset-confirm
POST/api/v1/auth/password/changeBearer token
07 · Accountability

A security history that avoids secrets

Sensitive actions create organization-scoped events that owners and admins can filter and paginate.

↳membership.updated2026-10-19 · owner
{ "role": "admin", "state": "active" }

Audit metadata uses an explicit allowlist. Passwords, raw tokens, authorization headers, and secrets are never accepted as metadata.

12 · Troubleshooting

Common setup issues

The readiness endpoint returns 503

Check that the MongoDB container is healthy and that MONGODB_URI points to the correct host. Inside Compose, use mongo, not localhost.

The application rejects the JWT secret

JWT_SECRET must contain at least 32 characters. Use a randomly generated secret outside local development.

Production mode will not start

Production intentionally requires complete SMTP settings: host, port, username, password, and sender address.

Invitation or reset email did not arrive locally

The development mailer does not send external email. Inspect docker compose logs api for the generated URL.
